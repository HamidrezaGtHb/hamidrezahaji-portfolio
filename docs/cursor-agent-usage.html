راهنمای استفاده از Cursor
برای پروژه Portfolio

چطور با کمترین توکن، ادیت‌های دقیق بزنی — بدون اینکه هر بار کل پروژه دوباره خوانده شود.

پروژه: hamidrezahaji-portfolio پلن: Cursor Plus تاریخ: نوامبر ۲۰۲۶
ایدهٔ اصلی در یک جمله
دانش ثابت پروژه داخل ریپو ذخیره شده است. تو فقط کار امروز را کوتاه بنویس، فایل‌های مرتبط را با @ بده، و چت تازه باز کن. لازم نیست دوباره داستان پروژه را تعریف کنی.

۱) این ستاپ چیست؟

قابلیت Projects در Cursor برای پلن Plus مناسب ذخیرهٔ دانش پروژه نیست. به جایش این‌ها داخل خود ریپو ساخته شده:

فایل / پوشه نقش کی به Agent داده می‌شود؟
AGENTS.md نقشهٔ کوتاه پروژه + قوانین کلی تقریباً همیشه
.cursor/rules/portfolio-core.mdc قوانین هسته‌ای خیلی کوتاه همیشه
.cursor/rules/*.mdc بقیه i18n، دیزاین، App Router فقط وقتی فایل مرتبط باز/ادیت است
.cursor/skills/ روندهای تکراری مثل دیپلوی یا کپی دو زبانه فقط وقتی لازم شود
.cursorignore جلوگیری از خواندن فایل‌های سنگین/بی‌فایده همیشه به‌عنوان فیلتر

۲) قانون طلایی مصرف توکن

  1. برای هر کار جدید، چت جدید باز کن. تاریخچهٔ بلند بیشترین مصرف را دارد.
  2. فقط ۱ تا ۳ فایل لازم را با @ منشن کن. کل پوشهٔ app/ را نده.
  3. اول Ask، بعد Agent. اگر فقط می‌خواهی «کجاست؟» بپرسی، Ask Mode کافی است.
  4. یک کار در هر پیام. مثلاً فقط فاصلهٔ سکشن، نه همزمان ریفکتور کل سایت.
  5. اگر Agent دو بار یک اشتباه را تکرار کرد، همان قانون را در Rules سفت‌تر کن — نه اینکه دوباره در چت توضیح طولانی بدهی.
کارهایی که توکن می‌سوزاند
چت خیلی طولانی نگه داشتن · فرستادن کل فولدرها · باز گذاشتن MCPهای بلااستفاده · گفتن «کل پروژه را بررسی کن» برای یک ادیت کوچک · ساختن PDF/داک اضافه بدون نیاز

۳) نحوهٔ استفادهٔ روزانه (گام‌به‌گام)

1 پروژه را در Cursor باز کن

همان پوشهٔ hamidrezahaji-portfolio. Rules و AGENTS.md خودکار دیده می‌شوند.

2 چت Agent جدید بساز

موضوع قبلی را ادامه نده مگر اینکه دقیقاً همان باگ/ادیت باشد.

3 فایل‌های هدف را با @ اضافه کن

مثال‌ها:

  • تغییر متن هیرو: @content/i18n.ts
  • تغییر فاصلهٔ سکشن‌ها: @styles/tokens.css
  • ادیت اسکرولر ورک: @components/WorkScroller.tsx و در صورت نیاز @components/WorkScroller.module.css
  • مسیر زبان: @middleware.ts

4 درخواست را کوتاه و مشخص بنویس

خوب
در هر دو زبان EN و DE، جملهٔ status هیرو را عوض کن به: Open to Product Design roles in Germany.
بد
یه نگاهی به کل سایت بنداز و هیرو و بقیه جاها رو بهتر کن و اگر لازم بود دیپلوی هم بکن.

5 نتیجه را چک کن

اگر کار درست بود و خواستی برود روی سرور زنده، صریح بگو: «کامیت، پوش و دیپلوی کن». بدون این جمله معمولاً دیپلوی نمی‌شود.

۴) چه چیزی از قبل داخل پروژه حفظ شده؟

دیگر لازم نیست این‌ها را هر بار توضیح بدهی:

  • زبان پیش‌فرض آلمانی است؛ انتخاب زبان با کوکی hh-lang یادآوری می‌شود.
  • کپی‌ها دو زبانه هستند: content/i18n.ts و پروژه‌ها در content/projects.ts.
  • رزومه: public/cv/en.pdf و public/cv/de.pdf.
  • توکن‌های طراحی در styles/tokens.css هستند.
  • روی موبایل باریک (زیر ۷۶۸px) ورک به صورت stack است؛ تبلت pinned می‌ماند.
  • دیپلوی: npx vercel --prod — بیلد لوکال اجباری نیست.

۵) Skills آماده در این پروژه

نام کی استفاده شود نمونه جمله به Agent
ship-vercel رفتن روی پروداکشن کامیت کن، پوش کن و دیپلوی کن
edit-bilingual-copy تغییر متن EN+DE متن About را در هر دو زبان کوتاه‌تر کن

لازم نیست اسم Skill را حفظ کنی؛ اگر منظورت واضح باشد Agent خودش می‌فهمد. اگر خواستی صریح بگو: «طبق skill مربوط به دیپلوی پیش برو».

۶) الگوی پیام‌های آماده (کپی کن)

تغییر کپی

@content/i18n.ts
در en و de، کلید hero.tagline را به این متن عوض کن:
EN: ...
DE: ...
فقط همین کلید. دیپلوی نکن.

تغییر دیزاین

@styles/tokens.css
مقدار --section-y را کمی کمتر کن تا سکشن‌ها فشرده‌تر شوند.
فقط توکن‌ها. کامیت نکن مگر بگویم.

باگ یک کامپوننت

@components/WorkScroller.tsx @components/WorkScroller.module.css
روی عرض ۳۹۰px کارت‌ها باید stack باشند.
علت را پیدا کن و با کمترین تغییر درست کن.

دیپلوی

تغییرات فعلی را کامیت و پوش کن، بعد vercel --prod.

۷) پروژه‌های بعدی تو

یک Skill شخصی به نام scaffold-agent-context روی سیستم تو نصب است. در پروژهٔ جدید بگو:

برای این ریپو همان ستاپ کم‌توکن Cursor را بساز
(AGENTS.md + rules + .cursorignore + skills لازم)

Agent از روی استک همان پروژه، نسخهٔ اختصاصی می‌سازد — لازم نیست این چت Portfolio را دوباره باز کنی.

۸) چک‌لیست ۳۰ ثانیه‌ای قبل از هر ادیت

  1. چت جدید؟
  2. می‌دانم کدام ۱–۳ فایل؟ اگر نه → اول Ask
  3. درخواست یک‌جمله‌ای و مشخص؟
  4. اگر متن است → هر دو زبان؟
  5. اگر باید زنده شود → صریح بگو دیپلوی
نتیجهٔ مورد انتظار
ادیت‌های معمولی Portfolio باید در چت‌های کوتاه، با چند فایل مشخص، و بدون توضیح دوبارهٔ تاریخچه انجام شوند. Rules کار حافظهٔ پروژه را می‌کنند؛ تو فقط کار امروز را می‌گویی.
